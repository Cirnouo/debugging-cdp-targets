# Thin host delivery regressions

The ten safe suites separate complete host assembly/source equality and literal
inventories (host-distribution), supplied metadata and maintained import boundaries
(host-metadata), PNG evidence (icon-packaging), strict trees and complete independent
audits (physical-payloads), portable registration (plugin-distribution), shared
presentation/source equality (skill-presentation), bilingual instruction contracts
(skill-questions), direct HTTP formats (thin-plugin-metadata), the six delivered
assembly/synchronization cases (thin-plugin-payloads) and version agreement.
Generic version predicates remain with the central software-version suite.

All60 original registrations and their helper/negative/cleanup matrices remain.
Three additional controls cover maintained import boundaries plus a forbidden-edge fixture,
ordinary tree bytes with independently optional link legs, and literal complete
host inventories. The standalone diagnostic records link capability skips locally;
ordinary tree assertions always run. Default/coverage explicitly select each suite
once; GUI authorization and native acceptance retain their separate owners.
YAML's locked token/warning diagnostics and SemVer's NODE_DEBUG behavior remain.
The metadata control pins three exact upstream bare process import edges; it also
exercises supplied JSON/YAML/artwork/version values and forbidden parent/specifier
pairs through the real handler. Import hooks cannot detect global environment reads;
maintained source review remains necessary. Ancestor test rules apply.
