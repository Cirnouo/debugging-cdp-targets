# Tests

Default regressions exercise the singleton App's reusable Core and direct SDK
HTTP boundary with explicit registrations and request facilities. Native/CDP
effects are replaced only at controlled I/O boundaries unless a test explicitly
owns a disposable native process. The retired per-chat stdio entry, automatic
host Tool Hooks and task-activity model are not current runtime interfaces.
Git hook tests remain contributor-tooling regressions.

  uncertain child retention and cleanup retry. It supplies no native execution
  evidence, and the preparatory modules are not imported by App startup.

Both default package test commands use `--test-concurrency=1`; the interactive
runner uses `node:test.run` with concurrency 1 to run files sequentially.
The interactive `window-evidence`, `screenshot-background-anchor` and `windows-native`
fixtures share the inherited Windows desktop and its single foreground window.
Concurrent files can foreground one owned fixture while invalidating another
file's required foreground observation. Process ownership does not isolate that
desktop state. Sequential file execution preserves every test, coverage floor,
native identity/handoff guard, assertion and deadline. Use the same option for
focused commands that combine foreground-sensitive native test files.

They are covered by the same strict no-emit typecheck as runtime and tooling.
