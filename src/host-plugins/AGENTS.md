Keep payload validation, endpoint evidence and byte overlays deterministic and free
of filesystem, process, environment and network I/O. Import only this domain,
existing pure domains and shared contracts. The exact `payload-integrity.ts`
owner may use `node:util` for pure comparison; other Node dependencies stay out.

Before editing `user-intent.ts`, selected configuration acquisition or the actual
`../adapters/native-host-plugins.ts` consumer, read cumulative
[selected-file instructions](native/AGENTS.md),
[ADR 0017](../../docs/adr/0017-singleton-desktop-app.md) and the
[accepted singleton plan](../../.superpowers/plans/2026-10-17-singleton-app-plan.md).
The pure `user-intent.ts` owner permits only `smol-toml`, the existing
`../domains/host-management.ts` and `../shared/errors.ts`. Keep its complete
own-intent projection, privacy, parser options and transition comparison together.
Only the native adapter and selected-file reader consume that owner. Only the
native adapter consumes the reader. These exact dependency roles also govern
erased imports; unknown Host/native siblings gain no I/O or ambient authority.

Filesystem reads, Claude leases and the complete atomic write/readback transaction
remain in `../adapters/verified-plugin-files.ts`. Git, receipts and management
retain their current owners. Only `native/user-intent-file.ts` owns the bounded
selected-file read under its local instructions; it grants no command authority.
